# Web版テスト方針

## 目的
Web版のルール変更・UI変更で既存の対戦機能を壊さないようにする。
現在のWeb版は `web/index.html` の単一ファイル構成を維持する。

## 自動テスト
- Node.js 22以上を使用する（追加のnpm依存なし）
- 実行コマンド：`node --test tests/*.test.cjs`
- HTML内のゲームスクリプトをNode.jsのVMで実行し、画面出力とゲーム状態を検証する
- GitHub Actions：`Webテスト`。develop/mainへのPRと更新時に実行する

## 検証範囲（初版）
1. 初期ライフ・結晶・山札・先攻攻撃制限
2. 召喚コストと結晶1個の配置
3. 熱い→冷めた→手元の冷却遷移
4. 対象指定マジックの不正対象・空振りによる資源消費防止
5. オーバードライブの反動と退場
6. カード一覧の表示・閉じる操作
7. 再戦時のゲーム状態初期化

## 手動確認が必要な項目
VMテストはSafariの実描画、画面サイズ、アニメーション、タップ判定、実際のCPUの速度を検証しない。
公開前にiPhone Safariで以下を確認する。

- 縦画面でカード一覧・ゲーム画面が横にはみ出さない
- カード一覧から閉じる操作ができる
- 相手の場が空のとき「結晶砕き」「凍結の霧」を使用できない
- 対象ユニットが現れた後は通常どおり使用できる
- 1戦を最後まで遊び、勝利・敗北・再戦が動作する

## 次の拡張候補
- CPU行動・プレイヤーブロック・勝敗の自動テスト
- Playwright等によるブラウザの画面・操作テスト
- ゲームロジックのモジュール分離（iOS展開前に検討）

## 運用
開発作業は原則 `feature/*` → `develop` のPRで進める。
`main` は公開版のため、レビュー・テスト後に `develop` からリリースする。
