# iOSバトルUI（俯瞰アリーナ・縦／横）

更新日: 2026-11-15 JST

## 最新の変更（v4）

中央プール・フェイズ表示・操作ボタン・進行案内を盤面中央の通常フローへまとめた。ターン終了やカード一覧がカード/HPを覆う絶対配置を撤去し、主要操作を実寸44px以上にした。5枚以上の手札はフラットな横スクロールに切り替え、1〜4枚は小さい扇形を維持する。詳細開閉やCPU描画でスクロール位置を保持し、再戦ではリセットする。先攻の攻撃制約と直近の進行案内を常時表示する。

召喚、結晶の増減、OD突入の演出はUI内の前回描画との差分から生成し、ゲームの判定に状態を追加しない。既存の攻撃/対象選択の演出も維持し、OSの動きを減らす設定ではアニメーションを停止する。

ブラウザの実レンダリング確認は `npm run test:ui`。8サイズ×5手札枚数、操作のヒットテスト、通し対戦、回転/余白を検証し、CIへスクリーンショットと失敗トレースを保存する。結果と修正前後画像は [qa-report.md](qa-report.md) を参照。実機は未確認でありDraftを維持する。以下は導入時からの設計/変更履歴を含む。

## 目的

参考画像のように、プレイヤーが対戦盤面を**斜め上から見下ろす構図**へ変更する。これまでの平面的な白／グレー分割画面を、石畳の卓上アリーナ、青（自軍）／赤（敵軍）の枠、盤面上にカードを置く構成へ刷新する。

変更対象は操作プレビューではなく **CapacitorのWebViewが実際に読み込む `web/index.html`**。ネイティブの `ios/` プロジェクト自体は従来どおりMacで生成する。

## 画面と操作

- **上部（相手）**: CPUアイコン、実際のライフ、相手の手札枚数（裏面だけ）、現在のターン、設定。
- **上側フィールド**: 相手のユニット最大4体と空枠。左にデッキ枚数、右に墓地枚数。
- **中央**: 左右を分ける床模様、中央プール、メイン→バトルの切り替え操作、ターン進行。
- **下側フィールド**: 自分のユニット最大4体と空枠。結晶の配置数、パワー、疲労やOD状態を表示。
- **下部（自分）**: アイコン、実際のライフ、手元／熱い／冷めた結晶、動的なカード枚数に対応する扇形手札。
- **中央操作行**: 攻撃フェイズへ、カード一覧、ターン終了。無効時は半透明。
- **カード操作**: 手札をタップ → 既存のカード詳細 → 召喚／マジック。自軍ユニットタップ → 結晶の増減／攻撃。対象指定中は敵カードをタップして確定。
- **盤面枠**: 自軍・相手軍それぞれ最大4枠のみ描画。横画面の旧追加5枠目も削除し、表示とルールを一致。

俯瞰は **CSS perspective + rotateX** を使った2.5D表現で、3Dエンジンや画像通信は必要ない。手札は枚数に応じて角度を変え、横幅不足ならスクロール可能にした。iOS端末ではセーフエリアに配慮する。

## 現行のルールを変更しない

参考画像の数値・UI概念はそのまま移植していない。

| 参考画像 | 実際に表示する内容 |
|---|---|
| HP 20 | ライフ結晶（初期5、現在値で更新） |
| マナ／MP 3/6 | 手元の結晶数、熱い／冷めた結晶数。5つのランプは装飾ゲージ |
| 攻撃力／防御力 | 左がユニットの**パワー**、右が**配置中の結晶数**。防御力ルールは新設しない |
| 5〜6枠の召喚スペース | 上限4体を維持。装飾用の追加枠は置かない |
| 相手の手札アート | 裏面だけを枚数に合わせ表示し、カード情報は公開しない |

カード12種、初期デッキ、召喚・OD・冷却・CPU行動・勝敗判定・対戦ログは従来と同じ。

## レイアウト再設計 v3（実機再確認待ち）

縦持ち／横持ちのスクリーンショットで見られた重なりと余白を、旧CSSの上書きの積み重ねではなくグリッドレイアウトで解消した。

- 画面全体を相手ヘッダー・盤面・プレイヤー領域の3行に分ける。上下の領域は盤面と重ならない通常フロー。
- 縦持ちはプレイヤー領域を「HP/結晶のHUD → 手札」に分割、横持ちは「HP/結晶 | 手札 | 補助操作」の3列を採用。
- バトルフィールド自体も「敵ユニット4枠 → フェイズ・中央プール → 味方ユニット4枠」のグリッドにし、割合指定のabsolute配置を廃止。
- CSSでの固定pxやパーセンテージは個別UIの最大サイズとグリッドの空き寸法にのみ利用し、ゲーム盤面全体の重なりを防止する。
- 旧来の横向き5枠目（操作できない装飾枠）をDOMから完全削除。
- CSSの2.5D奥行き表現とSVGアート、操作イベント属性、現在のライフ・結晶・墓地の動的描画は維持。

次の実機確認では **横画面の手札が盤面に重なっていないこと、縦画面の手札上端・下端が切れていないこと** を優先して確認する。
