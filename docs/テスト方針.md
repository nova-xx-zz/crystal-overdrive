# Web版テスト方針

## ブラウザUI回帰（2026-11-15追加）

`chromium-touch` プロジェクトはCDPのブラウザ入力を使い、手札が収まる4枚では動かず、あふれる5枚/20枚では左右に動いて端カードの詳細・召喚ができることを検証する。DOMのTouchEvent発火や `scrollLeft` の代入をスワイプ成功の根拠にしない。WebKitの表示/操作テストとは分離し、iPhone実機の入力は別途確認する。

`npm ci && npx playwright install --with-deps chromium webkit` の後 `npm run test:ui`。ブラウザ2種で320×568、375×667、390×844、430×932とそれぞれの横画面を検証する。満員盤面と0/1/4/10/20枚の手札、先頭/末尾の表示・ヒットテスト、主要入力44px、スクロール保持、詳細/一覧、召喚・結晶・OD・対象指定・ブロック・再戦、固定シードのCPU通し対戦を対象とする。

画面サイズの比較は固定画像の完全一致ではなく、実際の表示矩形・重複・画面外・入力を検査する。レイアウト用に直接設定する状態は描画フィクスチャであり、ゲームのカード総数の整合性を検証するケースではない。通し対戦はフィクスチャを使わずUI操作で進める。CIの `battle-ui-report` に画面・失敗時トレースを保存する。

回転/ノッチ相当の余白テストはCSSの予算検証であり、実機のSafe Area、VoiceOver、GPU性能、発熱、ホームバーを保証しない。iOS確認は別ゲートとする。

## 目的
Web試作版の対戦ロジックを保護し、将来のiOS移植時にもルールの差異を検出しやすくする。
正式な仕様の正本は [rules.md](rules.md)。仕様に変更があれば、実装・仕様書・テストを同じPRで更新する。

## 自動テスト
- 実行環境：Node.js 22（外部パッケージ不要）
- 実行コマンド：`node --test tests/*.test.cjs`
- 対象：初期状態、召喚コスト、結晶移動、冷却・劣勢補助、オーバードライブ反動、再戦時の非同期競合、対象指定マジックの操作制限、カード一覧表示
- 実行契機：`develop` / `main` 宛てのPR、`develop` への関連ファイルのpush
- 現在は `web/cards.js` → `web/decks.js` → `web/game.js` → `web/deck-ui.js` → `web/ui.js` をNode.jsのVMへ読み込んで検証する。画面を必要としないゲーム処理とデッキ検証の単独読み込みも確認する。

## iOS用コンテナの確認
- `capacitor.config.json` の `webDir` は `web`。リモートURLではなく同梱資材を利用する。
- `npm test` でiOS同梱設定、Capacitor依存の互換性、必要なJS/CSSの相対パスを確認する。
- Xcodeでのビルド・シミュレーター実行はこのCIでは検証できないため、[iOS起動手順.md](iOS起動手順.md) に従いMacで確認する。

## 実機・ブラウザでの確認
リリース前に少なくとも以下を確認する。
- iPhone Safari：縦画面で自分・CPUの盤面、手札、操作ボタンを確認
- 初手：召喚はできるが先攻1ターン目は攻撃できない
- 召喚とマジック：手元/熱い結晶が正しく増減する
- カード一覧：全12種の効果を閲覧でき、閉じて対戦に戻れる
- 対象指定：相手の場が空なら「結晶砕き」「凍結の霧」を使用できず、対象がいる場合のみ適用される
- 結晶の乗せ替え：最低1個を残し、上限+2個以上は置けない
- オーバードライブ：攻撃時効果とターン終了時の反動が一致する
- CPUの攻撃：ブロック選択、ブロックしない選択を試す
- 対戦中の「最初から」：古い対戦のCPU行動が新しい対戦に影響しない
- 勝利/敗北：結果画面と再戦を確認
- iPhone Safari：文字の欠け、横はみ出し、押せないボタンがない
- iPhone Safari：ホームインジケーターと下部操作バーの干渉、手札の横スワイプ、VoiceOverでの選択状態（[iPhone操作性.md](iPhone操作性.md)）

## ブランチ運用
通常の開発は `develop` から `feature/*` を切り、レビュー後に `develop` へPRで統合する。
`main` への反映は公開の区切りで別PRにする。Web公開ワークフローは `main` にだけ反応する。
