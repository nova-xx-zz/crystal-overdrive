# Web版テスト方針

## 目的
Web試作版の対戦ロジックを保護し、将来のiOS移植時にもルールの差異を検出しやすくする。
正式な仕様の正本は [rules.md](rules.md)。仕様に変更があれば、実装・仕様書・テストを同じPRで更新する。

## 自動テスト
- 実行環境：Node.js 22（外部パッケージ不要）
- 実行コマンド：`node --test tests/*.test.cjs`
- 対象：初期状態、召喚コスト、結晶移動、冷却・劣勢補助、オーバードライブ反動、再戦時の非同期競合
- 実行契機：`develop` / `main` 宛てのPR、`develop` への関連ファイルのpush
- 現時点では `web/index.html` のインラインJavaScriptをNode.jsのVMに読み込んで検証する。将来ロジックを分離したらテスト対象も移す。

## 実機・ブラウザでの確認
リリース前に少なくとも以下を確認する。
- iPhone Safari：縦画面で自分・CPUの盤面、手札、操作ボタンを確認
- 初手：召喚はできるが先攻1ターン目は攻撃できない
- 召喚とマジック：手元/熱い結晶が正しく増減する
- 結晶の乗せ替え：最低1個を残し、上限+2個以上は置けない
- オーバードライブ：攻撃時効果とターン終了時の反動が一致する
- CPUの攻撃：ブロック選択、ブロックしない選択を試す
- 対戦中の「最初から」：古い対戦のCPU行動が新しい対戦に影響しない
- 勝利/敗北：結果画面と再戦を確認
- iPhone Safari：文字の欠け、横はみ出し、押せないボタンがない

## ブランチ運用
通常の開発は `develop` から `feature/*` を切り、レビュー後に `develop` へPRで統合する。
`main` への反映は公開の区切りで別PRにする。Web公開ワークフローは `main` にだけ反応する。
