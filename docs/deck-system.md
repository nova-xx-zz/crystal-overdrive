# デッキ・ローカル保存設計

状態: 未着手（設計を記録、実行コードは固定デッキのまま）。M1の次の大規模タスクとして別featureで実装する。

## 仕様
- 20枚、同名最大2枚、存在するcardIdのみ。色制限は追加しない。
- 複数デッキの作成・名称編集・複製・削除・保存・選択。無効な編集中デッキも保存できるが対戦開始は拒否。
- 検索（名前/効果）、色・種類・コストフィルター、各カードの所持数/採用数、20枚と有効性を表示。
- 既存 `DECK_LIST` は初期保存デッキのコピー元とする。編集でマスターやCPUデッキを変更しない。
- M1はオフライン試用カードを各2枚利用可能とし、M2の獲得実績と混同しない。保存済みデッキのカード配列を検証してコピーしてからシャッフル。

## データ案（未実装）
`{schemaVersion:1, revision, decks:[{id,name,cards:[cardId],updatedAt}], activeDeckId, settings, collection:{source:'offline-starter', counts:{cardId:2}}}`。

純粋な `validateDeck(cards, master, inventory)` は枚数、同名超過、不明ID、所有不足を構造化して返す。表示用名称で照合しない。名前/IDはUIへ挿入する際エスケープ。対戦中のデッキへ編集を反映しない。

## 保存安全性
保存用キーを名前空間付きにする。JSON解析、サイズ上限、バージョン、型、非負整数、IDを検証する。バックアップと移行は読み出し/検証成功後だけ実施。破損/未知の将来バージョンを自動上書きせず、復旧案内とエクスポートを用意する。QuotaExceeded/利用不可時は成功表示を出さず、既存データを維持する。破壊的移行は承認が必要。
