# オンライン設計（M3、未着手）

iOS Capacitor/WKWebView → WebSocket → Node.js/TypeScript → PostgreSQL。M1の安定化とDOM非依存の共通エンジン化が前提。現時点でサービス契約・デプロイ・本番接続は行わない。

## 権威と可視情報
クライアントは `{matchId, requestId, expectedRevision, action}` の操作要求を送る。サーバーは認証と参加者認可、開始条件、所有を含むデッキ、ターン/フェイズ、手札、コスト、結晶移動、攻撃/防御、効果、勝敗、報酬を検証する。乱数と山札順序はサーバーのみが管理する。

プレイヤーごとに公開状態＋本人の手札へ投影し、敵の手札/山札順序は送信しない。エラー、ログ、再接続スナップショットにも漏らさない。ルールは共有エンジンを呼び、UI用の独立した勝敗判定を追加しない。

## 整合性と復帰
- 対戦単位で直列適用、revision比較、要求IDの一意制約と結果再送。認証済みでも古い/二重/範囲外要求を拒否。
- ブロック待ちとターン期限は明示的状態。期限はサーバー時計。切断猶予・期限切れ時の既定行動は実装前に仕様化。
- 再接続は本人認証後、最終revision以降のイベントまたは可視スナップショットから復帰。世代違いの通信を破棄。
- 勝敗→履歴→報酬を一意のmatchIdで一度だけ確定。ゲスト移行は所有の出所を検証し、オフライン申告を無条件に取り込まない。
- アカウント、デッキ同期、カジュアル、フレンドルーム、マッチング、降参をこの基盤へ接続する。

## 必須テスト（未着手）
同時操作、敵の操作/データ読み取り、期限の境界、重複要求、古いrevision、切断中攻撃、ブロック待ち切断、再接続、プロセス再起動、DB失敗、報酬重複、ユーザー分離、レート制限、メッセージサイズ/不正形式。
