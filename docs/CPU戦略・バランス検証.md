# CPU戦略・バランス検証

## 位置づけ
Web試作版のCPU対戦を改善するための設計書。正式な結晶ルールと12種のカード定義は [rules.md](rules.md) を正本とし、このフェーズでは変更しない。

## CPUの判断基準

### ブロック
1. 疲労していない味方からブロック候補を選ぶ。
2. 勝てる候補がいれば、相手のパワーを上回る中で最もパワーの低いユニットを優先する。過剰な戦力を温存する。
3. 相打ちにできて、こちらのカードコストが相手以下なら相打ちを選ぶ。
4. ライフが尽きる攻撃なら、相打ちを含め必ず防御し、勝てない場合は安価なユニットを犠牲にする。
5. 残りライフ2以下でも防御寄りに判断する。通常時は不利な相討ちや無駄な犠牲を避ける。

### オーバードライブ（OD）
- 行動可能・未OD・必要結晶を支払えるユニットだけを候補にする。
- ブロッカーがいない場合の決着打を優先する。次いでOD効果、パワー上昇、必要結晶を評価する。
- 上限の低いユニットはOD反動で失われやすいので、非決着時は評価を下げる。
- 相手ライフ3以上の通常時は従来どおり35%の発動抽選を残し、ライフ2以下なら抽選なしで候補を評価する。
- ただし、相手がブロックできる場合、強制的に決着を保証するものではない。

### 今後の改善候補
- メインフェイズで召喚とマジックの優先順位を比較する。
- 攻撃順の戦術、次ターンの敵ブロッカーと結晶回復を考慮する。
- CPU難易度（Easy / Normal / Hard）は現段階では実装しない。

## 自動対戦シミュレーター
テスト用プレイヤーボットが既存のゲーム関数でCPUと対戦する。固定シードを使い、同じ条件の結果を再現できる。

```sh
node scripts/balance-report.cjs --games 100 --seed 20261031
```

- `rush`：安価なユニットを優先し、結晶を積極的にLv2へ回す。
- `reserve`：少し結晶を残し、防御的な攻撃判断をする。
- ボットのブロック選択は簡易ルールで自動解決する。
- 指標：ボット勝率、CPU勝率、未決着件数、平均決着ターン、最短・最長ターン。
- ボットは人間の代替ではない。**実プレイヤーの勝率、ゲームの面白さや公平性を保証しない。**
- 結果はシード・試合数・方針・実装の版をセットで扱い、異なる条件を混ぜて比較しない。
- 試作版のUI、接続遅延、プレイヤーの熟練度はシミュレーションに含まれない。
- CIでは最小の再現性・集計テストを実行する。多数試合は開発時に任意で実行し、結果を仕様調整の参考にする。

## 手動確認
- 相手が強いユニットで攻めたとき、CPUが弱いユニットを適切に犠牲にできる
- 攻撃に勝てる場合、必要以上に強いユニットをブロックへ出さない
- 手元の結晶が足りないユニットのODを選ばない
- 相手のライフが残り2以下になった際、CPUが実行可能なODで追い込む
- iPhone Safariの対戦テンポ、ブロック待ち、結果画面に異常がない

## 変更管理
CPU戦略とカード数値の変更は原則別PRにする。大きなバランス変更を実施する前に計測結果を比較し、`develop` で検証してから `main` に公開する。
